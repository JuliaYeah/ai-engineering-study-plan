## 一面-3. workflow, agent, skill 区别
**English:**
A workflow is a predefined, deterministic sequence of steps where code orchestrates LLM calls — predictable and easy to debug, e.g. a RAG pipeline (retrieve → rerank → generate). An agent is autonomous: the LLM itself decides the next action in a loop — reasoning, calling tools, observing results — so it handles open-ended tasks where the path can't be fixed upfront. A skill is a reusable capability the agent can invoke: a function/tool definition, an MCP tool, or a packaged prompt-plus-tools bundle. In short: workflows fix the path, agents choose the path, skills are the tools available along the way.
**中文要点：**
- workflow：代码编排的固定流程，确定性高
- agent：LLM 自主循环决策（reason-act-observe），适合开放任务
- skill：可复用的能力包（function/MCP 工具），供 agent 调用

## 一面-18. SSE 是如何实现边生成边推送的？
**English:**
SSE (Server-Sent Events) is a unidirectional HTTP streaming mechanism. The server responds with `Content-Type: text/event-stream` and keeps the connection open, flushing each chunk as a `data: <payload>\n\n` event. For LLM generation, the server iterates over the model's token stream and writes each token (usually as a JSON delta) immediately, calling flush with buffering disabled (`X-Accel-Buffering: no`, `Cache-Control: no-cache`, chunked transfer encoding). The client consumes incrementally — via `EventSource` or the Fetch streaming reader — and appends tokens to the UI as they arrive. The stream ends with a sentinel like `data: [DONE]`. Unlike WebSockets, SSE is HTTP-based, auto-reconnects, and is ideal for server→client token streaming.
**中文要点：**
- HTTP 长连接，`text/event-stream`，`data: ...\n\n` 逐块推送
- 关键：关代理缓冲、chunked 编码、每 token 立即 flush
- 客户端用 EventSource/fetch reader 增量渲染；`[DONE]` 收尾
- 对比 WebSocket：单向、基于 HTTP、自动重连，适合 token 流式输出

## 一面-20. 手撕——快排
**English:**
Quicksort picks a pivot, partitions the array so smaller elements go left and larger go right, then recursively sorts both sides — average O(n log n) time, O(log n) stack space. Key interview points: Hoare vs Lomuto partition schemes; worst case O(n²) on sorted input with a naive pivot — mitigated by random/median-of-three pivot; 3-way partition handles many duplicates; an iterative version with an explicit stack avoids recursion depth issues.
**中文要点：**
- 思想：选 pivot → partition → 递归左右；平均 O(n log n)
- 注意点：随机/三数取中 pivot 防退化；重复元素用三路快排；可用显式栈改迭代
**Code (Python):**
```python
def quicksort(a, lo=0, hi=None):
    if hi is None:
        hi = len(a) - 1
    if lo >= hi:
        return
    p = partition(a, lo, hi)
    quicksort(a, lo, p - 1)
    quicksort(a, p + 1, hi)

def partition(a, lo, hi):
    pivot = a[hi]
    i = lo
    for j in range(lo, hi):
        if a[j] <= pivot:
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[hi] = a[hi], a[i]
    return i
```

## 二面-10. 什么情况下用 ReAct，什么情况下用 Plan and Execute？
**English:**
Use ReAct when the task is exploratory and the steps can't be known upfront — the agent interleaves reasoning and acting, deciding the next tool call based on the latest observation. It's flexible and simple, best for short-horizon tasks and debugging-style loops. Use Plan-and-Execute when the task is long-horizon and decomposable: the planner first produces a full step plan, executors carry it out, and a replanner adjusts on failure. It gives better global coherence, parallelization, and progress tracking, at the cost of higher latency and planning overhead. Rule of thumb: unknown path → ReAct; known-ish decomposition with many steps → Plan-and-Execute (with replanning).
**中文要点：**
- ReAct：边想边做，适合探索型、步骤不可预知的短任务
- Plan-and-Execute：先规划再执行 + 失败重规划，适合长链条、可分解任务，一致性好、可并行
- 经验法则：路径未知用 ReAct；能拆解的多步任务用 Plan-and-Execute

## 三面-8. 评测集和 Ground Truth 是如何构造的？
**English:**
Start by sampling real production queries and stratifying by task type and difficulty so the set mirrors actual usage. For ground truth: use human-annotated gold answers or golden tool-call trajectories for deterministic checks (exact match, tool F1, task success rate); for open-ended outputs, define a rubric and use LLM-as-a-judge calibrated against human labels. Version the dataset, keep a held-out split to prevent leakage, and continuously mine production failures to add regression cases.
**中文要点：**
- 从真实流量采样，按任务类型/难度分层，贴近线上分布
- Ground Truth：人工标注 gold 答案或 golden 工具轨迹；开放问题用 rubric + LLM-as-judge（先与人工对齐校准）
- 数据集版本化、留 hold-out 防泄漏；从线上 bad case 持续补充回归用例
