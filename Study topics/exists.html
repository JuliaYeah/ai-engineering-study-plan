How do you use EXISTS correctly, and what mistakes should you avoid?

怎样正确使用 EXISTS，应避免哪些错误？

Key Terms

EXISTS
EXISTS 判断是否存在匹配行，适合存在性过滤，避免为取右侧列而制造重复。
Row grain
一行数据代表的业务单位，例如一笔交易或一个账户。
NULL
未知或缺失值，不等同于零或空字符串。

直观例子

用账户和交易两张小表练习，加入一个没有交易的账户、一条缺失记录和重复数据。比较查询输出与手算结果，检查每行粒度。

Short Answer

For an anti-join I prefer NOT EXISTS when nulls are possible. NOT IN can become unknown if its subquery returns a null.

中文回答

EXISTS 判断是否存在匹配行，适合存在性过滤，避免为取右侧列而制造重复。NOT EXISTS 与带 NULL 的 NOT IN 行为不同。

Approach: For an anti-join I prefer NOT EXISTS when nulls are possible. NOT IN can become unknown if its subquery returns a null.

Complexity: a scan is O(n); sorting is commonly O(n log n); index access and joins depend on the actual plan. Inspect rows scanned, intermediate cardinality and spills rather than asserting one universal bound.

Edge cases: empty tables, nulls, duplicate keys, tied values, zero denominators and missing dates.

Reference SQL — reveal after your attempt
SELECT c.customer_id FROM Customers c WHERE NOT EXISTS (SELECT 1 FROM Orders o WHERE o.customer_id = c.customer_id);
