怎样正确使用 NULL，应避免哪些错误？

Key Terms

NULL
NULL 表示缺失或未知，普通比较可能返回未知。
Row grain
一行数据代表的业务单位，例如一笔交易或一个账户。
NULL
未知或缺失值，不等同于零或空字符串。

直观例子

用账户和交易两张小表练习，加入一个没有交易的账户、一条缺失记录和重复数据。比较查询输出与手算结果，检查每行粒度。

Short Answer

I use IS NULL, not equality to NULL. COUNT(column) skips nulls while COUNT(*) counts rows; I avoid replacing missing financial data with zero without a business rule.

中文回答

Interview Questions and Scripts

How do you use NULL correctly?

I use IS NULL, not equality to NULL. COUNT(column) skips nulls while COUNT(*) counts rows; I avoid replacing missing financial data with zero without a business rule.

Follow-up: What input would expose an incorrect assumption?

What row grain and duplicate behavior do you expect?

I define one output row before writing the query, inspect key uniqueness on both sides of each join, and test duplicate inputs. DISTINCT is not a general repair for an incorrect join.

Follow-up: Could a one-to-many join inflate a financial total?

How do nulls and ties affect this query?

I specify whether missing values should be retained, rejected or imputed. I use a deterministic tie breaker where one row is required and preserve ties when the business question asks for distinct ranks.

Follow-up: What happens to an unmatched row after a WHERE filter?

How would you test and optimize the query?

I build a tiny fixture with known expected rows, including duplicates and missing values. After correctness, I inspect EXPLAIN or Query Profile on representative data; runtime depends on cardinality, indexes and the execution plan.
