Tokenization|文本被转换成token编号；token不等于单词。实际token数决定输入长度和计费，应使用所选模型的分词器计数。
Next-Token Prediction|模型根据已有文本预测下一个token的概率。生成流畅不代表事实正确，也不能代替权限检查。
Context Windows|上下文窗口限制模型一次处理的内容。输入、检索证据和输出需共同规划；更长上下文不保证回答更好。
Temperature|温度调整采样概率分布，低温通常更集中。温度为零也不保证跨服务版本完全一致。
Top-p|Top-p保留累计概率达到阈值的一组候选token。应一次调整一个采样参数并验证效果。
Transformer and Attention Fundamentals|注意力通过query与key的匹配分数加权value表示。自回归模型用因果遮罩防止读取未来token。
LLM Limitations|模型可能编造事实、算错数字或受到恶意文本影响。引用证据、确定性计算工具及失败测试共同降低风险。
Model Selection|在实际任务上比较质量、延迟、成本和数据约束。公开榜单不能直接证明金融任务表现。
Prompt Engineering|提示应说明任务、输入、输出格式和限制，并用真实及对抗案例验证。提示不能替代缺失数据或服务端校验。
Few-Shot Examples|少量示例展示输入到输出的映射，包含模糊情况和拒答边界。示例须版本化，不能泄露测试答案。
Prompt Versioning|记录提示版本、模型、配置与评估结果，才能定位变更造成的退化并回滚。
Structured Outputs|结构化输出约束格式，但格式正确不等于内容正确。仍须检查字段、数值和业务约束。
Pydantic|Pydantic验证数据类型及约束，适合定义API和工具输入输出。业务规则仍需显式实现。
JSON Recovery|解析失败时可有次数受限的修复流程。不能静默改动金融数值，失败应保留诊断并明确返回。
Prompting vs. RAG vs. Fine-Tuning|提示定义任务，RAG提供可更新证据，微调改变模型行为。根据失败来源选择方案，先建立可测量的基线。
LoRA|LoRA训练低秩适配参数以减少可训练参数。仍需要合格训练数据、评估和部署兼容性检查。
Quantization|量化降低权重或计算精度以节省内存和可能的成本。须验证实际硬件上的速度及质量变化。
Embeddings|嵌入把文本映射为向量以比较语义。索引与查询须使用兼容模型，并在业务查询上验证。
Vector Similarity|向量相似度衡量表示的接近程度，不等于事实相关性。余弦与点积的含义取决于归一化方式。
Chunking|分块平衡语义完整性与检索粒度。块大小、重叠和文档结构应作为实验变量，而非固定最佳值。
Metadata|元数据保存来源、页码、日期、版本及权限。它支持过滤、引用和审计，不能由模型随意补造。
Context Budgets|分配系统提示、历史、证据和输出的token预算。增加证据可能增加成本并稀释重点，应测量质量收益。
Keyword / Vector / Hybrid Search|关键词适合精确术语，向量适合语义表达，混合检索合并两类信号。组合权重需用标注查询验证。
MMR|MMR平衡查询相关性与结果间多样性，可减少重复来源。它不保证一定覆盖多个来源，也不能保证召回所有相关证据。
Reranking|重排序对候选结果做更精细的相关性判断。它只能调整已召回候选，无法补救完全遗漏的证据。
Query Reformulation|查询改写可补充缩写或拆解复杂问题。保留原始意图并避免凭空加入实体或条件。
Citations|引用应映射到真实证据位置，并验证该证据支持具体主张。存在链接不代表主张得到支持。
Golden Datasets|固定标注数据用于比较版本，包含常见、困难和拒答案例。保留独立测试集，防止围绕同一题库过拟合。
Hard Negatives|困难负例看似相关但不能回答问题，例如同公司不同年份。它们帮助检验检索和拒答能力。
Held-Out Evaluation|保留数据不参与训练和调参，用于估计泛化能力。反复根据其结果修改系统会削弱独立性。
Recall@k|前k项召回率是找回的相关项占全部标注相关项的比例。它衡量覆盖，不能单独代表答案质量。
Precision@k|前k项精确率是其中相关项所占比例。它衡量结果纯度，应与召回率及成本一起看。
MRR|MRR平均第一条相关结果名次的倒数，适合关注首个正确结果的任务。它不衡量全部证据覆盖。
nDCG|nDCG结合分级相关性和位置折扣，评估排序质量。需要可靠相关性标注及清楚的评价范围。
Redundancy|重复结果占用上下文而不一定增加信息。测量重复程度并验证去重后是否损失重要证据。
Groundedness|有依据指回答主张得到提供证据支持。它不同于完整性，也不保证来源本身正确。
Hallucination|幻觉是生成不受证据支持或错误的内容。用证据约束、拒答及逐项校验减少，而不能宣称彻底消除。
LLM-as-Judge|用模型按评分标准评估输出，适合扩大评估规模。须用人工标注校准并监控偏差。
Human Calibration|人工复核建立评分标准并检查自动评估的一致性。关注分歧案例，不能只看总体平均分。
Judge Bias|评审模型可能偏好长度、表达风格或自己的输出。随机化展示顺序、隐藏模型身份并做人工抽查。
Offline / Regression Evals|离线评估比较固定案例上的版本表现，回归测试发现旧能力退化。不能替代上线后的真实监控。
Online Feedback|线上反馈反映真实用户行为，但受选择偏差影响。结合错误样本与离线指标判断。
Agents vs. Workflows|工作流步骤相对固定，agent动态选择下一步。只有任务确实需要动态决策时才增加agent复杂度。
Function Calling|模型提出工具名和参数，应用负责校验权限并执行。模型输出不是执行授权。
Tool Schemas|工具契约描述字段、类型、约束及错误。输入校验和权限控制应在服务端执行。
Tool Selection Evaluation|评估工具是否选对、参数是否正确以及该拒绝时是否拒绝。单纯任务成功率会掩盖危险调用。
Agent State|状态记录任务进度、工具结果及待批准操作。持久化与恢复应防止重复副作用。
Memory|记忆保存跨步骤或会话信息，需限制用途、权限和生命周期。过时或不可信记忆不能直接当作事实。
LangGraph|LangGraph用状态和图结构组织流程、分支与恢复。工具权限和业务正确性仍由应用负责。
Termination Conditions|停止条件包括成功、步数、时间、成本和重复失败上限。达到限制应返回可解释状态。
MCP Fundamentals|MCP标准化工具与资源的连接方式。协议连通不代表服务器可信或调用已获授权。
REST APIs|REST API以资源和HTTP语义表达操作。设计状态码、错误格式、认证、分页及幂等行为。
FastAPI|FastAPI提供Python API路由、数据验证和接口文档。耗时任务需避免阻塞请求处理。
API Tests|接口测试验证请求、响应、权限与错误边界。应覆盖业务不变量和失败情况，而非只测成功路径。
Workers|worker处理后台任务，应记录状态、限定资源并处理重启。重复投递不能重复产生业务副作用。
Idempotency|同一逻辑请求重复执行应产生一次业务效果。键须绑定请求内容并明确保存期限。
Timeouts|超时限制等待时间，但不证明远端未执行成功。对有副作用请求需状态查询或幂等保障。
Backoff|退避让重试间隔逐步增长，加入随机抖动减少同步重试。还需总截止时间和次数上限。
Rate Limiting|限流限制单位时间请求量。它不同于并发上限，两者都可能需要。
Backpressure|背压在下游变慢时限制上游输入，防止队列无限增长。可采用有界队列、拒绝或延迟接收。
Docker|容器封装应用运行环境，帮助一致部署。需固定依赖版本、限制权限并管理镜像和配置。
CI/CD|持续集成自动验证变更，持续交付组织发布。测试通过不等于生产安全，仍需部署验证和回滚。
Cloud Fundamentals|云服务提供计算、存储及网络资源。理解费用、权限和故障边界后再选择托管服务。
IAM|IAM控制身份能对哪些资源做哪些操作。按最小权限配置并避免长期共享密钥。
Networking|网络设计涉及连接、路由、DNS与访问边界。排错先确认请求在哪一跳失败。
Capacity Planning|根据到达速率、服务时间和资源瓶颈估算容量，再用负载测试验证。平均值之外还需考虑峰值。
Load Testing|负载测试测量不同压力下的延迟、错误及资源占用。使用接近真实请求分布并找出饱和点。
Logs|日志记录事件及错误上下文，使用关联ID串联请求。避免记录密钥和敏感原文。
Traces|追踪连接一次请求的多个处理步骤，定位检索、工具或模型延迟。记录必要元数据且保护敏感信息。
p50 / p95|p50是中位延迟，p95表示95%的观测不超过该值。分位数须在同一测量窗口和请求群体上比较。
TTFT|TTFT是请求开始到首个token的时间。它影响响应感受，但不代表完整回答的耗时。
Streaming|流式返回逐步展示结果，改善等待体验。需处理取消、部分失败及结构化内容未完成的状态。
Token Usage|记录输入输出token以估算成本和上下文压力。应按模型实际计数与计费规则核对。
Caching|缓存复用结果以减少耗时与成本。键应包含影响结果的版本、参数和权限范围。
Semantic Caching|语义缓存复用相近请求，存在错误匹配风险。对数字、日期和权限敏感查询需更严格限制。
Freshness|新鲜度描述数据是否仍适用于当前问题。定义更新时间、失效条件并展示来源时间。
Model Routing|按任务难度或约束选择模型，可能减少成本。路由规则需验证质量并保留失败升级路径。
Cost-Quality Trade-offs|在可接受质量门槛下比较模型、检索和上下文的实际成本。不能只优化token而忽略错误代价。
Human-in-the-Loop|高影响操作在执行前交给人审核。审核界面应展示具体参数、影响和依据。
Approval Audit Trail|审计记录谁批准了哪次操作、参数和时间。批准须绑定具体操作，参数变更应重新判断。
Prompt Injection|恶意输入试图让模型越过原任务或泄露数据。把外部文本当数据，限制工具权限并测试攻击样本。
Tool Sandboxing|沙箱限制工具能访问的文件、网络和资源。应在执行环境强制限制，而非只依赖提示。
PII|个人可识别信息需最小化收集、限制访问并定义保留期。日志及评估数据也需要保护。
Access Control|访问控制验证用户是否能读取或操作资源。检索前和执行时都要落实，不能只隐藏界面。
Tenant Isolation|租户隔离防止不同客户数据混用。数据库、检索、缓存和日志均需明确租户范围。
Secrets|密钥应存入专门的密钥管理系统，避免进入代码、日志和提示。使用短期凭据并支持轮换。
Fail-Open vs. Fail-Closed|失败放行优先可用性，失败拒绝优先保护边界。权限检查通常应拒绝，具体选择由业务风险决定。
Graceful Degradation|部分依赖失败时返回受限但明确的服务，例如仅展示已验证证据。不能静默降低准确性。
Snowflake|Snowflake提供云数据仓库，查询需受权限、成本和资源限制。生成SQL执行前仍须校验。
Text-to-SQL Evaluation|评估SQL语义、执行结果、权限和拒答，不只比较字符串。不同SQL可能表达同一正确查询。
SEC Financial Data|SEC数据包含申报、期间、单位和修订信息。使用时核对实体、时间、口径和来源。
Data Quality|数据质量包含完整性、一致性、及时性与正确性。缺失值和单位错误应在模型前被发现。
Point-in-Time Data|时点数据只允许使用当时已公开的信息。期末日期不同于披露日期，混淆会造成未来泄漏。
Experiment Tracking|记录数据、代码、参数和指标版本，使实验可以比较和复现。只存最终分数不足以解释结果。
Failure Recovery|恢复需识别已完成步骤、持久化状态和可安全重试边界。防止重启后重复写入或执行。
Latency Benchmarking|统一请求、并发、窗口及计时范围测量延迟。区分冷启动、缓存命中与正常请求。
AWS ECS Fargate|Fargate运行托管容器任务，需配置资源、网络、角色及健康检查。应用仍要处理状态和部署故障。
ECR|ECR存储容器镜像。使用不可变版本或摘要，并管理访问及镜像扫描。
CloudWatch|CloudWatch收集日志、指标和告警。告警阈值应对应可采取的动作而非只制造噪声。
GitHub Actions|GitHub Actions自动运行验证和发布流程。限制凭据权限，并保护部署分支和工作流。
OIDC|OIDC可用身份令牌换取短期云权限，减少长期密钥。信任条件须限制仓库、分支及受众。
Clean-Environment Reproduction|在干净环境按文档安装并运行项目，检验隐含依赖。固定版本并提供可用示例数据。
README|README说明目标、安装、运行、限制和验证方法。读者应能按步骤复现演示。
Demo|演示展示真实输入、结果、依据和失败处理。说明数据与效果范围，避免夸大生产能力。
Ownership|拥有项目意味着能解释设计、检查代码、定位故障及承担结果。AI写代码不替代这些责任。
AI-Assisted Code Review|检查AI生成代码的需求匹配、权限、异常、复杂度和测试。不能仅因运行成功就接受。
Design Trade-offs|设计取舍说明需求、候选方案、收益与代价。通过规模、风险或延迟约束解释选择。
Risk Copilot|Risk Copilot应把风险分析结论连接到可核验数据和计算，并测量检索与答案质量。展示你能解释及改进的实现。
Financial Statement Analytics Assistant|财报分析助手重点是口径、单位、期间和受控SQL。数值计算应由确定性工具完成并保留来源。
Investment Research Workbench|研究工作台组织数据、实验、评估和结果追踪。可恢复运行与可复现证据比堆叠agent更重要。
SQL|SQL用于查询和聚合结构化数据。先明确每行粒度、连接关系与空值语义，再写查询。
Queues and Workers|队列解耦任务提交与执行，worker消费任务。考虑重复投递、重试、状态和死信处理。
Retries|只对适合重试的暂时故障重试，设置退避和总预算。有副作用操作必须具备幂等或状态查询。
